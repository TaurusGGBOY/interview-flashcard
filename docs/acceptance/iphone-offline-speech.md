# 物理 iPhone 离线语音转写验收

Simulator 只能验收语音按钮门控、权限失败、录音界面、转写确认和提交链路。语音功能最终签收还必须在一台物理 iPhone 上证明 Apple Speech 的设备端转写在断网时可用。本检查不使用 DeepSeek，AI provider 保持确定性本地 stub，音频不得上传。

## 前置条件

- 从要签收的当前 checkout 构建并安装 Debug App，记录 branch、commit、Xcode 版本、iPhone 型号、iOS 版本和 App bundle ID。
- 在联网状态下确认目标识别 locale 已下载设备端语音模型；App 的能力诊断必须显示该 locale 支持本地识别。
- 允许 Interview Flashcard 使用麦克风和语音识别。若系统请求新权限，由用户亲自确认；验收者不能自行修改隐私与安全设置。
- 使用不含个人、公司或题库敏感信息的短测试答案。为证据目录准备 `context.txt`、`steps.md`、操作前后屏幕证据、App 日志、诊断 `state.json` 和本地音频文件元数据。

## 离线检查表

- [ ] App 已在断网前安装并打开到语音回答页，AI provider 为 stub。
- [ ] 开启飞行模式，并明确关闭 Wi-Fi；屏幕证据同时显示飞行模式开启和 Wi-Fi 关闭。若蓝牙保持开启，记录原因，它不能提供网络连接。
- [ ] 在断网状态下重新进入语音回答页，语音按钮仍因设备端能力可用而启用。
- [ ] 点击录音并用真实麦克风说出一段预先记录在 `steps.md` 的测试答案，随后停止录音。
- [ ] 界面在无网络时显示非空转写文本，内容足以与口述答案对应；没有转圈等待网络、云端降级或联网提示。
- [ ] 转写确认页允许编辑文字；做一个可见的小修改，并确认提交内容使用修改后的文字。
- [ ] 提交后产生 Answer Attempt，原始转写/编辑文本可在历史中查看。后续润色与评分只能由本地 stub 完成，不能借此证明真实 DeepSeek 可用。
- [ ] App container 的 Application Support 中存在本次录音对应的本地 M4A，文件非空；`state.json` 中的 attempt 和 audio asset ID 与界面一致。
- [ ] App 日志证明转写路径设置了设备端识别要求，且没有执行云端语音 fallback 或音频上传。
- [ ] 在整个转写开始到确认文本出现期间，飞行模式保持开启且 Wi-Fi 保持关闭；据此记录“转写期间没有可用网络，也没有发生网络请求”。若任何网络接口恢复，本次检查作废并从头重跑。

## 必须保存的结论

`steps.md` 必须逐项写明：使用的 locale 和本地模型状态、真实口述内容、可见转写、人工编辑、提交后的 attempt ID、本地 M4A 路径与字节数、诊断状态核对，以及以下结论：

> 本次转写全程处于飞行模式且 Wi-Fi 关闭；转写期间没有可用网络，也没有发生网络请求；音频只保存在本机 App container，未上传。

如果本地能力不可用、离线时按钮被禁用、无法产生文字、只能保留录音、出现云端降级、音频被上传、M4A 缺失或 UI 与状态不一致，语音功能均不得签收。恢复网络只允许发生在全部离线证据采集完成之后。
