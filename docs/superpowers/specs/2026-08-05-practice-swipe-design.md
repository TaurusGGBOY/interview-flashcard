# 练习卡片左右滑动交互设计

## 目标

把练习页的一张题目卡片改成类似交友应用的拖拽卡片，同时保留现有的 Topic 筛选、纯随机抽题、“包含已练习题”开关、文字/语音回答和回答历史能力。

这不是传统的“右滑表示答对、左滑表示答错”闪卡评分。用户必须先自己回答，参考答案和 AI 评分只在提交回答后出现。

## 已确认的交互语义

- 卡片正面只展示 Topic 和面试题，不展示满分答案。
- 向左拖过提交阈值：标记为跳过并抽取下一张卡片；不创建 `AnswerAttemptRecord`，不影响“已练习”状态。
- 向右拖过提交阈值：卡片向右退出并进入当前题目的 `AnswerEditorView`；此动作本身不创建回答记录。
- 右滑后用户可以输入文字或使用可用的本地语音转写；提交后沿用现有的润色、六维评分、历史和参考答案展示流程。
- 右滑进入回答页后返回但未提交：原题仍视为未练习，可以再次被抽到。
- 当前抽题范围和 `includePracticed` 行为不变，开关继续默认关闭。
- 跳过时，如果抽题池中有其他题目，下一题不立即选择当前题；如果池中只有当前题，则允许再次显示它。

## 视觉与手势反馈

卡片使用原生 SwiftUI `DragGesture`，只处理水平位移：

- 卡片跟随手指水平移动，并轻微按位移产生旋转；垂直位移不触发操作。
- 向左拖动时在卡片上显示红色 `跳过` 标签和 `xmark` 图标；向右拖动时显示绿色 `开始回答` 标签和 `pencil.and.outline` 图标。
- 提交阈值为卡片可用宽度的约 32%，或达到明显的水平投掷速度；未超过阈值时卡片使用弹簧动画回到原位。
- 超过阈值后卡片在约 0.22 秒内滑出屏幕，再执行对应动作，避免视觉上突然换题或突然跳转。
- 卡片底部同时保留“跳过”和“开始回答”两个可访问按钮，按钮与手势执行完全相同的动作。
- 首次进入卡片页显示一次简短提示：`左滑跳过 · 右滑开始回答`；不增加教程流程，也不持久化复杂的新手状态。

## 页面状态和导航

`PracticeView` 继续使用现有的 `filters`、`card`、`empty` 三个阶段。新增的状态只负责当前手势和导航：

- `dragTranslation`: 当前拖拽位移，用于卡片偏移、旋转和覆盖层透明度。
- `isSwipeInFlight`: 防止手势动画期间重复触发按钮或第二次拖拽。
- `answeringCardID`: 右滑完成后通过 `navigationDestination(item:)` 打开 `AnswerEditorView`。
- `showSwipeHint`: 控制一次性的轻量提示；不改变抽题或持久化模型。

手势提交和按钮提交共用同一个动作函数，避免“按钮能进回答页、手势却有不同语义”。回答页退出后，现有的 `cards.map { $0.attempts.count }` 监听负责重新计算当前卡片是否仍在抽题池中：提交过且未开启“包含已练习题”时自动抽下一题，未提交则保留原题。

## 数据流

```text
筛选条件 → QuestionDrawService.eligibleCards
        → 展示一张 QuestionCardSnapshot
        → 左滑/点击跳过 → 从同一抽题池排除当前题后重新抽题
        → 右滑/点击开始回答 → AnswerEditorView
        → 用户提交 → AnswerSubmissionService
        → 保存 AnswerAttemptRecord → AI 润色 → 六维评分
        → 评分结果页显示参考答案、历史和分数
```

左右滑动不新增 SwiftData 实体、不改变回答历史模型，也不把“开始回答”误记为练习。

## 组件边界

- `PracticeView.swift`：卡片布局、拖拽视觉、按钮入口、筛选和导航状态。
- `PracticeSwipeInteraction.swift`：纯值类型的阈值和动作判定，供视图和测试共同使用；不依赖 SwiftData 或 UIKit。
- `AnswerEditorView.swift`：保持现有文字/语音输入、提交、处理状态和结果页；只接受右滑传入的题目 ID，不提前加载或展示满分答案。
- `QuestionDrawService.swift`：继续负责合格题目筛选和随机抽题；跳过时由 `PracticeView` 传入排除当前题后的池，不改变服务的随机算法。

## 无障碍与失败处理

- 手势不是唯一入口；两个按钮有明确中文标签和稳定的 accessibility identifier。
- VoiceOver 用户可以通过按钮完成同样的跳过/开始回答动作；拖拽覆盖层不会隐藏题干。
- 快速重复操作在动画完成前被忽略，避免重复导航或连续抽题。
- 抽题池为空时继续使用现有空状态页，并提供返回筛选入口。
- 题目在右滑后被删除或移入回收站时，回答页沿用现有“题目不存在”状态，不创建空回答。

## 测试与验收

### 自动化测试

- 为 `PracticeSwipeInteraction` 覆盖：未达阈值回弹、左滑跳过、右滑开始回答、垂直拖动不触发、速度触发、单题池排除失败后回退。
- 保留现有 `QuestionDrawServiceTests`、`AnswerSubmissionServiceTests` 和语音能力测试，验证模型和回答链路未被改变。

### Computer Use 验收

设备固定为 iPhone 17 Pro Max（iOS 27.0，UDID `779ACF98-BD23-4880-9F03-8DB9B9E43768`），通过 Xcode beta 的 Device Hub 启动当前 checkout 构建的 App。

验收路径：

1. 进入练习页，选择有题目的 Topic，保持“包含已练习题”关闭并开始练习。
2. 确认首张卡片只有题干，没有满分答案。
3. 真实拖拽向左，确认卡片离场并出现另一张题目；随后从诊断状态确认没有新增回答记录。
4. 真实拖拽向右，确认进入同一题的回答页，且页面没有提前展示满分答案。
5. 输入确定性测试回答并提交，确认出现处理状态、六维分数和提交后的参考答案；从本地诊断状态确认新增一条回答记录。
6. 返回练习页，确认提交过的题目在默认关闭“包含已练习题”时不会继续留在抽题池；打开开关后可以再次抽取。
7. 重复路径使用底部按钮各执行一次，确认按钮与手势结果一致。

证据目录为 `diagnostics/mac-ui/practice-swipe/`，包含当前构建/启动日志、操作前后截图、Computer Use 操作记录和本地状态读回。

## 不在本次范围内

- 不实现传统闪卡的 Again/Hard/Good/Easy 记忆评级。
- 不增加第三方卡片堆栈依赖或新的后端服务。
- 不修改 Markdown 导入、AI 拆题、50 题批处理、题目删除/回收站或评分算法。
- 不在右滑时预览、翻转或自动显示满分答案。
