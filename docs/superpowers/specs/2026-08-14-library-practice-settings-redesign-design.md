# 题库、练习与设置页重做设计

## 目标

统一调整练习页、题库页、题目编号、Topic 删除交互和设置页布局，使题库浏览与批量操作更清晰，同时移除新的语音回答/语音转写入口。现有导入、评分、回答历史和回收站数据必须保持可用。

## 已确认的产品规则

- 题目编号是全库递增的永久唯一整数，不显示 `#`。
- 编号在题目导入最终激活时确定；手动新增题目继续使用下一个编号。
- 题目编号不会因为移动 Topic、删除题目或重新导入而复用。
- Topic 内的题目按编号从大到小显示。
- 题目长按进入多选；多选状态下点击任何非题目区域立即退出多选。
- Topic 不进入多选状态，也不提供 Topic 批量删除。
- Topic 只能通过左滑删除；确认后删除 Topic 及其全部题目。
- 语音回答整块从回答页移除，不再提供新的录音或本地语音转写功能。

## 方案选择

### 推荐：保留现有 SwiftUI + SwiftData 架构，做边界清晰的增量改造

在现有 `LibraryView`、`AnswerEditorView`、`SettingsView` 和 `TopicService` 上收敛交互，把编号分配和 Topic 级联删除抽成可测试的服务。这样可以复用当前导入、评分、历史和回收站链路，改动集中且便于在实体机上验证。

### 备选：重写题库为新的导航/集合架构

可以彻底重做 Topic 列表和题目列表，但会同时改变搜索、展开、题目详情和批量移动的状态管理，风险明显高于本次需求的收益。

### 不采用：用 UUID 或创建时间临时计算显示编号

这种做法不能满足“导入时确定、永久唯一、删除后不复用”的要求，也无法保证不同导入批次之间的稳定顺序。

## 数据与编号设计

### QuestionCardRecord

为 `QuestionCardRecord` 增加可选的 `questionNumber: Int?` 持久化字段。可选性只用于兼容旧 store；应用启动完成数据准备后，所有未编号题目都必须获得编号，新增题目也必须在保存前获得编号。业务层不依赖 UUID 作为用户可见编号。

新增 `QuestionNumberingService`，负责：

1. 查询当前所有题目的最大编号。
2. 为新题分配下一个整数，从 1 开始，删除的编号不回收。
3. 按 `createdAt` 升序、UUID 升序为旧题回填编号，保证同一数据集重复启动时结果稳定。
4. 在导入激活阶段按候选题目的 `sourceOrder` 升序分配编号，确保 Markdown 顺序决定编号顺序。

导入激活和手动新增都在当前主 ModelContext 上完成编号分配，并与题目插入一起保存。移动 Topic 不改变编号。

为了兼容当前已经存在的 SwiftData store，模型增加字段时采用轻量迁移兼容路径；启动 bootstrap 会执行一次回填并保存。测试夹具可以显式提供编号，未提供时由编号服务补齐。

## 练习页设计

### 回答标题

当 `AnswerEditorView` 以闪卡背面模式展示时，不再设置“练习”导航标题，顶部保留系统导航返回行为但不显示这两个字。普通独立回答入口继续使用“回答”标题。

### 文字回答

回答页只保留题目卡、文字编辑器、提交按钮、评分状态和评分结果。提交路径统一调用文字提交接口；回答结果页和历史详情页继续复用当前完整评分展示。

### 语音功能边界

移除回答页的语音回答卡片、能力检查、录音和本地转写入口，并移除新的语音权限请求。`AnswerInputMode.voice`、`AudioAssetRecord` 和历史数据的只读处理可以保留，以便旧数据能够继续显示或被回收站清理；新版本不再创建语音回答记录，也不再暴露语音转写功能。

## 题库页设计

### 顶部和 Topic 标题

- 移除右上角“完成”“选择题目”“选择 Topic”模式按钮。
- 保留导入、手动添加、回收站等已有操作入口。
- 移除工具栏中的新建 Topic 按钮，把加号放在 `Topics` 区域标题右侧。
- Topic 行不再显示选择圆圈、Topic 多选状态或 Topic 批量删除底栏。

### Topic 与题目卡片

Topic 行和题目行使用独立的圆角背景、细边框和稳定内边距，使每一项边界明确；继续支持展开/收起 Topic。

展开 Topic 后，题目按 `questionNumber` 降序排列。每道题显示“编号 + 题目短句”，题目保持单行截断；搜索结果也显示编号和所属 Topic，并沿用同一题目行样式。

### 题目多选

- 普通点击题目仍进入题目练习/回答流程。
- 长按题目进入题目多选，并自动展开可见 Topic。
- 多选状态下点击题目只切换该题选中状态。
- 底部操作区仅提供全选、更改 Topic、退出选择；不在右上角增加完成按钮。
- 点击 Topic 标题、列表空白、搜索结果外区域或其他非题目内容时，立即清空选择并回到普通浏览状态。
- 批量更改 Topic 继续使用现有下拉选择 + 确定流程，题目编号保持不变。

### Topic 左滑删除

普通 Topic 行提供左滑删除动作；系统 Topic“待分类（Others）”不提供该动作。用户触发删除后，显示系统确认弹窗，明确列出 Topic 名称、题目数量和“删除 Topic 及其中全部题目，且不可撤销”的影响。确认后由 TopicService 一次性删除 Topic 及其卡片、回答、评分和关联记录，并在保存成功后清理这些旧语音记录对应的本地音频文件；取消则不改变任何数据。

## 设置页设计

### 根设置页

移除当前嵌套 DisclosureGroup。根页改为清晰的分组列表：

- “服务”分组：AI 服务、练习设置，每行显示图标、标题、当前摘要和 chevron，点击进入独立页面。
- “安全与隐私”分组：使用独立说明卡展示 API Key 存储、数据发送范围和本地数据边界。
- 根页不直接展开长表单，避免多个设置控件堆叠在同一屏。

### AI 服务页

按“服务商”“连接配置”“操作”“安全提示”分组展示 Picker、Base URL、模型、API Key、测试连接和保存按钮。测试状态和错误信息只出现在操作分组内。

### 练习设置页

按“题目范围”“主题选择”“说明”分组展示主题开关、全选、已练习题开关和说明文字；主题列表使用系统 `List` 行样式，保持 Dynamic Type 和深色模式可读。

## 删除与历史兼容

Topic 删除是本次新增加的不可撤销级联删除；题目自身仍按现有回收站规则处理。历史评分页面继续使用 `EvaluationResultView`，不因题库行样式或语音入口移除而改变既有评分历史展示。

## 测试与验收

### 单元测试

- 编号从 1 开始分配，连续分配不重复。
- 删除题目后再次分配不复用旧编号。
- 旧题回填按创建时间和 UUID 稳定排序。
- 导入激活按 `sourceOrder` 分配编号，并按 Topic 查询结果降序排列。
- 手动新增题目获得全库下一个编号。
- Topic 删除拒绝系统 Topic，确认级联删除后 Topic、题目、回答、评分和音频记录均不存在。
- 题目批量移动不修改编号。
- `AnswerEditorView` 的正常提交路径不再依赖语音能力或录音器。

### 模拟器实际操作验收

1. 打开题库，确认加号位于 Topics 标题右侧，右上角不再出现选择模式按钮。
2. 展开 Topic，确认题目卡片边界清晰、编号存在且从大到小排列。
3. 长按题目进入多选，批量移动后点击 Topic 标题或空白区域，确认立即退出多选。
4. 左滑 Topic，确认出现删除动作；取消确认不删除，确认后 Topic 与题目一起消失。
5. 进入回答页，确认没有“练习”标题和语音回答区域，文字回答仍能完成评分。
6. 打开设置，确认根页和 AI/练习子页分组清晰，没有嵌套展开导致的拥挤布局。

## 不改变的内容

- Markdown 导入、AI 拆题/润色/分类、评分和历史评分结果的业务语义不变。
- 批量移动题目仍由下拉选择目标 Topic 后点击确定完成。
- 回收站中的题目恢复、永久删除和音频清理规则保持有效。
- 不修改现有 API Key、AI provider 或并发策略。
