# 题库已回答标志设计

## 目标

让用户在题库浏览题目时，能立即分辨哪些题目已经提交过回答，同时保持现有题目行简洁，并避免与批量选择状态混淆。

## 已确认规则

- 一道题只要存在至少一条已持久化的回答记录，就视为“已回答”。
- 回答提交后，即使后续 AI 评分失败，也仍然显示已回答标志。
- 没有提交过回答的题目不显示标志。
- 回答次数和最高分不在本次范围内。

## 呈现设计

在普通浏览状态下，于题目行右侧显示绿色 SF Symbol `checkmark.circle.fill`。标志同时出现在 Topic 展开后的题目列表和搜索结果中。

批量选择模式使用独立的选择圆圈。为避免两个勾同时出现造成歧义，已回答标志在批量选择模式下暂时隐藏；退出批量选择后恢复显示。

题目文字继续保持现有单行截断规则。标志位于固定尾部，不挤占编号，也不改变题目排序、点击、长按或导航行为。

## 数据与组件边界

直接使用 `QuestionCardRecord.attempts` 关系判断是否已有回答，不新增持久化字段、缓存、哈希或迁移。该关系在回答提交保存后更新，因此能覆盖等待评分、评分中、评分失败和评分完成状态。

把“是否已回答”的判断封装为可测试的领域属性或小型辅助逻辑；`LibraryView` 仅负责根据该状态渲染标志。Topic 展开行和搜索结果行复用同一标志视图，避免两处样式或无障碍行为漂移。

## 无障碍与平台规范

- 使用系统绿色与 SF Symbol，自动适配浅色和深色模式。
- 标志是非交互元素，不新增触控目标。
- 普通浏览状态下，题目行的 VoiceOver 标签包含“已回答”；未回答题目不附加该状态。
- 不只依赖颜色表达状态，小勾形状与无障碍文本共同传达含义。

## 测试与验收

### 自动化测试

- 没有回答记录时，题目状态为未回答。
- 存在正常回答记录时，题目状态为已回答。
- 存在后续评分失败的回答记录时，题目状态仍为已回答。

### 界面验收

1. 展开 Topic，确认回答过的题目右侧显示绿色小勾，未回答题目不显示。
2. 搜索题目，确认搜索结果沿用相同标志。
3. 长按进入批量选择，确认已回答标志隐藏，只显示选择状态；退出后恢复。
4. 提交回答并返回题库，确认对应题目出现小勾，包括评分失败的回答。
5. 使用深色模式和 VoiceOver 检查标志可辨识且题目朗读包含“已回答”。

## 不改变的内容

- 不改变回答提交、AI 评分、历史记录或题目排序逻辑。
- 不增加数据库迁移或冗余状态字段。
- 不显示回答次数、分数或最近回答时间。
