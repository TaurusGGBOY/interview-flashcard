# Interview Flashcard 功能设计

本文档记录 grilling 会话中已经确认的产品设计。领域术语以根目录 `CONTEXT.md` 为准，重大取舍见 `docs/adr/`。早期研究文档若与本设计或已接受 ADR 冲突，以本设计和 ADR 为准。

## 产品定位

这是面向个人 iPhone 使用的面试题卡应用。用户从 Markdown 导入面试资料，按 Topic 抽题，用文字或语音作答，获得 AI 润色、评分和满分答案，并查看历史与复习统计。数据以本地存储为主。

## Topic 与 Others

- 用户可以创建 Topic；AI 无权创建 Topic。
- 每张题目卡片恰好属于一个 Topic。
- `Others` 是系统内置的待分类主题，不能被当成普通知识分类。
- AI 无法在已有 Topic 中可靠分类时，将题目放入 Others。

## Markdown 导入与题卡生成

每次 Markdown 导入都形成独立的源文档；即使重复导入相同内容，也不做识别、跳过或历史关联。

超长源文档被切成可以重叠的导入分片。AI 对每个分片自由拆题，本地 Markdown 结构不决定题目边界。分片输出先成为候选题目，不立即进入抽题池。

同一源文档的候选题目按原始顺序组成整理批次，每批最多 50 题，最后不足 50 题也单独成批，不与其他源文档混合。AI 在批次内执行题卡整理和去重：统一题干表达、消除对源文档上下文的依赖、整理满分答案，但不得改变考点或添加源文档没有的事实。去重只保证单个整理批次内部，跨批次重复不处理。

所有整理批次完成后，结果成为可抽取的题目卡片，不设置人工逐题审核。

## Others 重新分类入口

“题库管理”页面顶部固定显示 `待分类（Others）` 功能卡片，并显示当前待分类题目数量。点击卡片进入独立的待分类页面；系统不因新建 Topic 自动发起重新分类。

待分类页面提供一个主要操作 `AI 重新分类`。该操作处理触发时 Others 中的全部题目，不提供逐题勾选。题目按每批最多 50 题调用 AI；AI 只能返回已有 Topic 或 Others，只改变 Topic，不修改题干和满分答案。

成功批次立即保存分类结果。调用失败的批次直接跳过，其中题目继续留在 Others，任务继续处理后续批次。任务结束后只显示简单完成提示，不提供逐题结果或单批重试；用户下次重新运行时，仍在 Others 的题目会再次参与。

## 删除与回收站

删除题目卡片时，经用户确认后将题目及其全部回答历史一起放入回收站。回收站不自动清空；用户可以恢复，只有明确执行永久删除时才销毁数据。

## 回答方式

题目支持文字回答和语音回答。语音按钮只有在当前设备能够完成本地转写时才可用；不支持时按钮处于不可用状态，不提供云端转写或仅保存录音的替代路径。语音音频只保存在本地，转写文字由用户确认后进入与文字回答相同的提交、润色和评分流程。

## 随机抽题

用户可以选择一个或多个 Topic 组成抽题范围，并通过“包含已练习题”开关决定是否抽取已经提交过回答的题目；该开关默认关闭。仅抽到、查看或跳过不算练习过。

抽题采用纯随机：所有满足筛选条件的题目卡片等概率，不根据 Topic 的题目数量做均衡或配额调整。每次只显示一张题目卡片；用户可跳过当前题，或在提交完成后点击“下一题”再抽取，不预先生成固定题单。跳过不产生回答历史。

如果当前抽题范围为空，页面只需说明没有符合条件的题目，并允许用户返回修改 Topic 或“包含已练习题”开关；不为该状态增加智能推荐。

## 信息架构

应用采用五个一级入口：

1. `练习`：选择 Topic 和筛选项，随机抽题并作答。
2. `题库`：管理 Topic、Others、Markdown 导入、题目卡片和回收站。
3. `历史`：按时间查看全部回答历史，并进入单题历史。
4. `统计`：查看练习量、分数和维度趋势。
5. `设置`：配置 DeepSeek API Key、AI 模型和隐私说明。

题库页中的 Others 固定置顶，但不作为独立一级 Tab。满分答案、回答历史和来源信息从题目卡片详情进入。

## 题目卡片与满分答案

每张可抽取题目卡片至少包含：题干、所属 Topic、当前满分答案、来源文档和来源定位。缺少题干或满分答案的候选题目不能完成题卡整理。

满分答案由 AI 在题卡整理阶段依据源文档生成，目标是形成可独立阅读、覆盖关键点的参考答案。它不得添加源文档没有的事实。当前版本至少包含：简洁回答、关键点、必要解释、示例或取舍（源文档存在时）以及常见遗漏。

练习过程中，满分答案在提交前保持隐藏，避免直接泄题；提交并完成评分后展示。用户也可以从题目详情查看满分答案。满分答案采用版本记录，回答历史关联评分当时使用的版本，后续更新不会改变旧评分上下文。

## 回答与提交

文字回答直接在题目页编辑。语音回答先本地录音并在设备端转写，转写完成后进入同一个文本编辑区，用户可修改后提交。数据库保存用户最终确认的原始文本；语音模式另保存本地音频相对路径和转写文本。

提交按钮只在回答含有非空文字时可用。点击提交后立即创建回答记录并固定以下内容：题目版本、满分答案版本、原始回答、回答方式和提交时间。随后启动作答润色与评分；用户可以留在处理页等待，也可以离开，稍后从历史中查看结果。

提交成功即意味着该题成为已练习题，不以 AI 是否评分成功为条件。同一题允许提交多次，每次都形成独立回答历史，旧记录不被覆盖。

## 作答润色与 AI 评分

AI 流程必须拆成两个独立步骤：

1. `作答润色`：只改善表达、结构和输入法/设备端转写造成的可恢复问题，不得补充用户未表达的知识事实。
2. `回答评分`：读取题目、评分使用的满分答案版本、原始回答和润色回答，输出结构化评分。

评分不能只看润色文本。若某个知识事实只出现在润色结果、原始回答中没有表达，该事实不得贡献正确性或覆盖度分数。界面同时保留并展示原始回答与润色回答，让用户能够检查 AI 是否改变原意。

总分为 0–100，MVP 使用固定的六维评分规则：

| 维度 | 权重 | 含义 |
|---|---:|---|
| 正确性 | 35% | 技术事实和结论是否正确 |
| 覆盖度 | 25% | 是否覆盖满分答案中的核心知识点 |
| 推理与原理 | 15% | 是否解释原因、机制或推导过程 |
| 结构与清晰度 | 10% | 回答是否有逻辑且容易理解 |
| 示例与取舍 | 10% | 是否给出恰当示例、边界或权衡 |
| 准确简洁 | 5% | 术语是否准确，是否避免无关冗余 |

客户端根据各维度分数和固定权重计算总分，不直接信任模型返回的总和。评分结果还包含：做得好的点、遗漏或错误、下一次改进建议、评分置信度以及使用的模型、提示词和 rubric 版本。

AI 返回必须通过 JSON 结构、取值范围和完成状态校验。润色或评分因网络、限流或无效响应失败时，回答记录仍然保留并标记处理失败；历史详情提供一次明确的“重新处理”操作。重新处理产生新处理版本，不修改原始回答。

## 回答历史

`历史` 一级入口按提交时间倒序显示回答记录，支持按 Topic 和题目筛选。列表至少显示题目、提交时间、总分或处理状态、回答方式。

回答详情展示：

- 当时的题干与满分答案版本；
- 原始回答；
- 润色回答；
- 总分及六个维度分数；
- 做得好的点、遗漏/错误和改进建议；
- 语音回答的本地录音回放；
- 使用的模型、评分规则版本和处理状态。

题目卡片详情提供该题的历史时间线，使用户能比较多次回答。删除题目进入回收站时，其全部回答历史一同隐藏；恢复题目后历史恢复可见。永久删除题目时才删除关联回答、评分、润色版本和音频文件。

## 复习统计

统计只基于已经提交的回答记录，不把查看或跳过计算为练习。MVP 提供以下指标：

- 题目总数、已练习题数、未练习题数和覆盖率；
- 回答次数、练习天数、最近 7 天和 30 天练习量；
- 总分平均值、最新值和最佳值；
- 六个评分维度的平均值与时间趋势；
- 按 Topic 的题量、练习覆盖率和平均分；
- 最近回答和低分题目的快捷入口。

统计同时保留“题目覆盖”和“回答次数”两个口径，避免重复回答同一题夸大覆盖率。MVP 不实现 FSRS、遗忘曲线预测、连续打卡奖励或自动生成复习队列；复习通过开启“包含已练习题”并选择 Topic 完成。

## AI 与隐私边界

DeepSeek 是 MVP 的 AI 提供商。模型标识必须配置化，不在数据模型中写死；API Key 由用户输入并存入 Keychain。所有 AI 请求都由 iPhone 客户端直接发起，不建设应用后端。

允许发送给 DeepSeek 的内容仅包括完成当前任务所必需的文本：源文档片段、现有 Topic 名称、题目、满分答案、评分规则以及用户确认提交的文字回答。语音音频永不上传。设置页明确提示 Markdown 和回答文字会发送给 DeepSeek，并提供清除 API Key 的操作。

设备端语音转写是语音按钮的硬性能力条件。应用优先使用系统提供的设备端 Speech 能力；运行时能力检测失败、语言模型不可用或用户拒绝麦克风/语音权限时，语音按钮不可用，文字回答保持可用。

## 本地数据与实体边界

结构化数据使用 SwiftData 保存在设备本地；语音录音使用 M4A 文件保存在 Application Support，数据库只保存相对路径、时长和必要校验信息；DeepSeek API Key 使用 Keychain。MVP 不启用账号、服务器数据库或跨设备同步。

核心实体及责任如下：

| 实体 | 责任 |
|---|---|
| `Topic` | 用户认可的知识分类，包括系统内置 Others |
| `SourceDocument` | 一次 Markdown 导入及其来源信息 |
| `ImportRun` / `ImportChunk` | 跟踪源文档的分片拆题和处理进度 |
| `QuestionCandidate` | 分片拆题得到、尚未整理的临时题目 |
| `RefinementBatch` | 同一源文档中最多 50 个候选题目的整理单元 |
| `QuestionCard` | 已整理、可抽取且恰好属于一个 Topic 的题目 |
| `ReferenceAnswerVersion` | 题目卡片的满分答案版本 |
| `AnswerAttempt` | 一次不可覆盖的用户提交及处理状态 |
| `PolishResult` | 一次作答润色结果及模型/提示词版本 |
| `Evaluation` | 总分、维度分、反馈、置信度和 rubric 版本 |
| `AudioAsset` | 语音回答的本地录音元数据 |
| `ReclassificationRun` | 手动发起的 Others 全量重新分类任务 |

详细字段和版本关系参考 [数据模型与 AI 评分规格](../../research/data-model-and-ai-scoring.md)。

## 关键数据流

### Markdown 导入

`选择 Markdown → 建立源文档 → 生成重叠分片 → AI 自由拆出候选题目 → 同源每 50 题组成整理批次 → AI 题卡整理与批内去重 → 校验 → 创建题目卡片`

一次导入可以选择一个或多个 Markdown 文件，但每个源文档独立执行，不混合整理批次。导入界面显示文档级进度和最终生成题数，不提供逐题审核。

拆题或整理请求遇到临时错误时自动重试一次。仍然失败则该源文档标记为导入失败，不激活该源文档的部分题目；用户可以继续该导入任务。继续处理属于同一个 SourceDocument，不等同于再次导入。

### 作答评分

`抽到题目 → 输入文字或本地转写 → 用户确认并提交 → 保存 AnswerAttempt → 作答润色 → 多维评分 → 展示结果与满分答案 → 下一题`

### Others 重新分类

`题库管理 → 待分类 → AI 重新分类 → 每 50 题调用 AI → 成功结果立即保存 → 失败批次跳过 → 简单完成提示`

## 技术结构

推荐采用 Swift 6、SwiftUI、SwiftData、AVFoundation、Apple Speech、Swift Charts、Keychain 和 `swift-markdown`，通过 Swift Package Manager 管理依赖。应用按能力边界拆成以下模块：

- `Library`：Topic、题目、来源、导入、Others 和回收站；
- `Practice`：抽题范围、随机选择、文字/语音回答和提交流程；
- `AI`：DeepSeek 请求、结构校验、版本记录与重试；
- `History`：单题及全局回答历史；
- `Insights`：本地统计聚合和图表；
- `Persistence`：SwiftData、音频文件和 Keychain。

Markdown AST 仅用于保护结构、形成分片和追踪来源，不负责决定题目边界。超长 Markdown 的方案与取舍参考 [专项调研](../../research/long-markdown-ai-decomposition/research-report.md)。

## 错误与边界处理

- 没有 Topic 时仍可导入，所有题目归入 Others。
- AI 返回未知 Topic 时按 Others 处理，不自动创建 Topic。
- 抽题范围为空时不重复弹错，只提示修改筛选条件。
- 提交后 AI 失败不丢失回答，历史中显示失败并允许重新处理。
- 重新分类批次失败时直接跳过，不阻塞后续批次。
- 永久删除必须二次确认，并明确显示将同时删除的回答记录和音频数量。
- App 被中断后，可从持久化状态继续未完成导入或查看正在处理/失败的回答。

## Mac Computer Use 验收协议

每个功能都必须在 macOS 上使用 Computer Use 操作当前代码构建出的 iOS Simulator 完成验收。单元测试、构建成功、日志或静态截图都只是辅助证据，不能替代真实点击、输入、滚动和可见结果检查。

### 单功能验收合同

开始实现一个功能前，先为该功能写明：

- 使用的 Simulator 设备和 iOS runtime；
- App 启动入口和完整用户路径；
- 操作前的测试数据；
- 每一步应看到的界面结果；
- 操作后应产生的本地状态；
- 用于独立确认状态的测试、数据库查询、日志或文件读回；
- 证据目录 `diagnostics/mac-ui/<feature-slug>/`。

验收时固定执行以下步骤：

1. 记录当前分支、commit 和工作区状态，确认不是旧构建。
2. 运行该功能相关的快速非 UI 测试。
3. 从当前 checkout 构建并启动 App 到指定 iOS Simulator，保存构建与启动日志。
4. 使用 Computer Use 检查 Simulator 窗口，确认窗口可见、非空白、没有旧 App 或错误遮罩。
5. 使用真实 UI 输入完成验收合同中的用户路径；操作前后通过 macOS `Cmd+Shift+3` 保存全屏截图。
6. 从 UI 之外读回 SwiftData、文件、日志或测试接口状态，确认界面与持久化结果一致。
7. 将操作步骤、截图、日志、命令和状态证据保存到该功能的 diagnostics 目录。
8. 停止本次启动的进程并保留可重复执行说明。

以下任一情况均判定失败：窗口空白或被旧窗口遮挡；无法通过 Computer Use 完成主要路径；界面显示成功但本地状态不一致；只有测试通过而没有真实 UI 操作；证据缺少当前 commit、截图或独立状态读回。

### MVP 功能验收矩阵

| 功能 | Computer Use 必走路径 | 独立证据 |
|---|---|---|
| Topic 管理 | 打开题库、创建 Topic、查看列表 | SwiftData 中存在 Topic |
| Others 入口 | 打开固定入口、发起全部重新分类、看到完成反馈 | Topic 归属变化及未匹配题仍为 Others |
| Markdown 导入 | 从 Simulator 的 Files 选择测试 Markdown、观察导入进度、进入生成题目 | SourceDocument、QuestionCard 数量和来源锚点 |
| 随机抽题 | 多选 Topic、切换“包含已练习题”、连续抽题 | 抽取结果属于当前 Draw Pool |
| 文字回答 | 输入文字、提交、查看处理状态与结果 | AnswerAttempt、PolishResult、Evaluation |
| 语音能力门控 | 在不支持本地转写的测试条件下确认语音按钮不可用；在能力测试配置下走录音与确认文本 UI | 能力检测日志及本地 AudioAsset；真实本地转写另做真机检查 |
| AI 润色与评分 | 使用确定性 AI 测试响应完成提交，查看原文、润色文和六维分数 | 结构化响应校验日志和本地评分记录 |
| 回答历史 | 从全局历史和单题详情打开同一回答 | UI 内容与 AnswerAttempt 版本一致 |
| 统计 | 完成预置回答后查看覆盖率、平均分和趋势 | 独立聚合测试结果与 UI 数字一致 |
| 回收站 | 删除题目、从回收站恢复、再次查看回答历史 | 软删除状态与关联记录保持；不在自动验收中永久删除用户数据 |
| 错误恢复 | 注入 AI 失败，确认回答不丢失；重新分类失败批次被跳过 | 失败状态、后续批次状态和日志一致 |

Computer Use 验收优先使用确定性测试数据和本地 AI stub，避免每次验收依赖网络、消耗 DeepSeek 额度或把私人题库/回答发送出去。真实 DeepSeek 集成作为单独 smoke test；若需要在 UI 中输入或保存 API Key，必须在执行该敏感操作前由用户明确确认。

设备端语音识别无法仅靠 Simulator 完成真实性验收。该功能仍必须在 Mac 上用 Computer Use 验证按钮门控、权限失败、录音 UI、转写确认 UI 和后续提交链路；同时增加一条物理 iPhone 真机检查，证明目标语言能在断网条件下完成本地转写。两类证据缺一不可。

## MVP 范围与验收

MVP 必须完成：

1. 创建、查看和管理 Topic，以及系统 Others。
2. 从 Files 导入 Markdown，并通过 AI 分片拆题、题卡整理、满分答案生成、批内去重和 Topic 分类创建题库。
3. 多选 Topic、默认排除已练习题、纯随机一次抽一张。
4. 文字回答；能力支持时使用本地语音转写回答。
5. 提交后保存原文，执行作答润色和六维评分，并展示满分答案。
6. 查看全局及单题回答历史，包括原文、润色文、具体分数和语音回放。
7. 查看练习覆盖、分数趋势、维度趋势和 Topic 统计。
8. 手动从独立入口重新分类全部 Others。
9. 本地持久化、Keychain 密钥管理、回收站恢复与永久删除。

上述每一项都必须有独立的 Mac Computer Use 验收合同与 `diagnostics/mac-ui/<feature-slug>/` 证据目录。没有真实 Simulator UI 操作和独立状态读回的功能不得标记完成。

核心验收场景是一条完整闭环：创建 Topic，导入包含长 Markdown 的题库，AI 生成可抽取题目，选择 Topic 随机抽题，用文字或本地语音回答，提交后得到原文/润色文、多维分数和满分答案，再从历史与统计中看到该记录。

## 明确不做

- 账号、登录、应用后端和多人协作；
- 云端语音转写或上传音频；
- 人工逐题审核导入结果；
- AI 自动创建 Topic；
- 跨整理批次或重复导入的全局去重；
- 跨设备同步、社区题库或公开内容分发；
- FSRS、智能复习调度、排行榜和游戏化；
- Android、Web 或 App Store 商业发布流程。
